# Design: CLI 教材以互動對話為主線

## Architecture
保留靜態教材架構，調整教學順序與範例文字。Markdown 配對章節同步 HTML；獨立 HTML 章節直接修正其操作片段。

## Components
章首只教啟動與對話；實作以 text 區塊呈現自然語言，保留來源、受眾、要求與輸出。進階內容呈現會話延續、context 管理、token 用量及模型選擇，先查核兩款工具官方文件再寫出各自支援的介面操作。批次處理示範透過對話請 Agent 規劃、產生、解釋與執行腳本。規則檔使用獨立段落連至單元五。

## Interfaces
使用現有檔名與網址，不改導向或圖片。保留各章實作任務與學習目標；重複的兩套提示合併為兩種工具共用的一份。

## Error Handling
提示指定新產物檔名，要求完成後檢查檔案；工具授權不足時檢查設定。不可把自然語言要求當成 sandbox 保證。由 Agent 建立的腳本仍須檢查失敗與空輸出處理；不將 session 視為無限記憶，也不將 token 用量等同帳單金額。

## Testing Strategy
使用既有靜態教材檢查器檢查連結與配對內容；搜尋單次指令與啟動附帶 prompt 的殘留，確認不再用於推薦操作範例；查核 session、context、用量及模型操作的官方依據。瀏覽代表性的入門與長實作頁面，檢查桌面、手機、導覽及提示區塊。此為編輯工作，不執行付費模型任務或安裝指令。

## Decision Log
| Decision | Options Considered | Chosen | Reason |
|---|---|---|---|
| 一般案例 | 每次 shell 執行／同一會話提問 | 同一會話提問 | 符合使用者要求及漸進追問情境 |
| 自動化 | 指令附帶 prompt／對話委託 Agent | 對話委託 Agent | 使用者要求進階亦以互動介面為主 |
| 提示格式 | bash／text | text | 明確辨識輸入位置 |
