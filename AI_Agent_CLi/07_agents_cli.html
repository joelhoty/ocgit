AI Agent 是什麼？

AI Agent 是由模型、context、工具與執行控制組成的系統：根據目標提出下一步，工具執行後把結果回傳，再決定繼續或交付。自主程度由任務、權限與 harness 決定；它會犯錯，完成宣告不等於已通過驗收。

典型組件包括感知（讀到的輸入與工具結果）、規劃（拆成可執行步驟）、記憶／context 管理（本次可用資訊與持久指引）、工具使用（讀寫檔案、執行命令或連接服務）。並非每種 Agent 都有完整長期記憶；硬碟上存在的資料也不表示模型已經讀取。

AI Agent 可以做些什麼？

  • 軟體開發：閱讀專案、提出修改、實作及執行測試，讓人依差異與結果驗收。
  • 資料分析：清理已授權資料，列出統計假設、程式與輸出，人工抽查原始列。
  • 研究整理：在可用的搜尋工具與網路權限下讀來源，分清資料支持的結論與推論。
  • 個人助理：透過另外設定的工具處理行程或草稿；發信、發布等外部動作需明確授權。

常見的 AI Agent 應用場景

場景 適合交付的任務 人的驗收責任
軟體工程 一個有測試條件的修正 測試、差異與相容性
客戶服務 根據政策整理回覆草稿 核對政策與必要的人工核准
科學研究 整理資料、比較假說 檢查來源、設計與推論限制
智慧家庭 在已設定的裝置權限內調整排程 裝置安全、例外狀況及人員需求

這是工作方式的例子，不代表安裝任一 CLI 後就自動取得上述服務與權限。

AI CLI 是什麼？

CLI 是命令列介面。Codex CLI 與 Claude Code 讓使用者在專案目錄中交付自然語言任務，再由產品整合的模型與工具處理。shell 仍以固定語法執行指令；AI 會產生命令或工具請求，不會讓任意中文變成有效的 PowerShell 語法。

AI CLI 可以做些什麼？

自然語言可用於產生腳本、解釋程式、搜尋檔案、修改教材與診斷錯誤。例如「列出這個專案最大的五個檔案」需要先選正確 shell、指定目錄及排除 .git；應要求回報命令與結果，不能只看一張沒有來源的表格。

常見的 AI CLI 應用場景

開發者可撰寫測試與文件；系統管理員可先產生維運腳本再審閱；資料工作者可建立 Python／SQL 分析；學習者可要求解釋錯誤並建立最小可重現案例。CLI 本身不包含所有編譯器、Python 套件或外部服務，任務依賴仍須配置。

OpenAI Codex CLI 與 Claude Code

兩者都是可在終端機操作的 Agent 產品，不是單一模型的名稱。前者以 codex 啟動，後者以 claude 啟動。本課先練共通的「目標、資料、限制、產物、驗收」，再比較各自命令，避免把一家參數套到另一家。

AI CLI 與 AI Agent 的關係

CLI 描述操作入口，Agent 描述工作方式，兩者不是自主程度的高低排名。具有工具回饋迴圈的 CLI 可以執行多步任務；網頁產品也可能連接 Agent 與遠端環境。真正要問的是：模型看到了哪些資料、工具在哪裡執行、誰核准動作、如何證明完成。

AI CLI 的獨特優勢：與本機環境整合

一般未連接本機工具的聊天視窗，需要人工上傳或貼上資料；CLI 能在授權範圍內直接讀寫專案並呼叫測試工具。這不是「網頁永遠無法讀檔」：網頁也可能提供檔案上傳、連接器或遠端執行環境。本機執行工具亦不等於模型離線運算；送給服務的 context 仍需遵守資料規範。

應用場景：自動化專案重構與驗證

情境：JavaScript 專案把 getUserProfile() 換成 src/utils/api.js 的 fetchUserProfile()。先確認新函式參數與回傳值相容，檢查 Git 狀態並留存版本，再進入 codex 或 claude 貼上：

先閱讀 package.json、舊函式與新函式實作，列出受影響的呼叫位置。
比較參數、回傳值及非同步行為，再提出最小修改。
依各檔案位置加入正確的相對 import，不要硬套 /src 絕對路徑。
完成後執行專案現有測試；回報命令、退出碼、修改檔案與剩餘風險。
若依賴尚未安裝，先說明缺項，不要宣稱測試通過。

工作流程是理解相容性、搜尋引用、逐檔修改、執行驗證、回報差異。工具呼叫由 CLI 根據可用能力與權限決定；提示中不需要虛構 @shell 指令。驗收時看 git diff、測試結果及未追蹤檔案，不能只因文字看起來合理就提交。

以 Codex CLI 與 Claude Code 為例（詳細指南）

核心特色

兩者都能協助讀寫檔案、執行專案命令及延續會話；搜尋、MCP 與其他整合依設定與帳號而異。價格與配額會變動，本教材不承諾固定免費額度。先確認登入方式、方案及組織權限，再安排課堂實作。

0. 安裝前置需求：依安裝路線選擇

原生安裝路線不要求先裝 Node.js；npm 路線需要 Node.js/npm。Python、C++ 編譯器是執行相應作業所需，不是兩款 CLI 的共同安裝先決條件。Windows 以 PowerShell 為主，macOS 使用 Terminal；命令應與 shell 相符。

1. 安裝 Codex CLI 或 Claude Code

a) 官方原生安裝（課程主線）

系統／安裝方式 Codex CLI Claude Code
Windows PowerShell（新視窗） powershell -ExecutionPolicy Bypass -c "irm https://chatgpt.com/codex/install.ps1 | iex" irm https://claude.ai/install.ps1 | iex
macOS／Linux／WSL 終端機 curl -fsSL https://chatgpt.com/codex/install.sh | sh curl -fsSL https://claude.ai/install.sh | bash
macOS Homebrew（替代） brew install --cask codex brew install --cask claude-code
Windows WinGet（Claude 替代） 本課不列未查核的 CLI 套件名稱 winget install Anthropic.ClaudeCode

表格的 | 是管線字元。每款工具只選一種安裝方法，避免多份執行檔搶用 PATH。下載腳本會在本機執行；學校電腦請使用管理員核准的安裝路線。這些指令在 shell 執行，不貼到 AI 對話中。

安裝後重新開終端機，選所用工具檢查：

codex --version
# 或選 Claude Code：
claude --version

查核：2026-10-31。Codex 安裝、Windows CLI 部署、Claude Code 安裝。

b) 使用 npm（已有 Node 環境時的替代）

先確認 node --version 與 npm --version；選受支援的 Node LTS，Claude npm 安裝目前要求 Node 22+。只執行所選工具的一行：

npm install -g @openai/codex@latest
# 或
npm install -g @anthropic-ai/claude-code@latest

更新 npm 安裝也使用同一行。npm 管理的是套件安裝；Claude 目前下載原生執行檔，執行時不依賴你的 Node。不要由「npm 安裝」推論所有 CLI 的 runtime 都一樣。

c) 使用 Homebrew（macOS 替代）

使用上表 cask。更新時執行 brew upgrade --cask codex 或 brew upgrade --cask claude-code。Claude claude-code 追蹤 stable；如果選 claude-code@latest，安裝與更新都應使用同一 cask 名稱。不要混用原生與套件管理器的更新方式。

2. 設定與驗證

a) 帳號與登入方式

Codex 可透過 ChatGPT 登入或 API key；Claude 可使用具資格的 Claude 帳號、Console 或組織提供的服務。訂閱授權與 API 計費不相同；模型清單與功能以登入後實際可用內容為準。Codex 認證、Claude 入門。

b) 啟動與驗證登入

mkdir teaching-project
cd teaching-project
git init
codex
# 或在同一專案選用：claude

第一次啟動依提示完成瀏覽器登入。需要重新登入時，在 shell 用 codex login 或 claude auth login；不要使用舊教材中的 config set api_key。成功判準：能看見正確專案目錄並完成一個讀檔任務。版本號印出僅代表指令可執行，不代表帳號已授權。

3. 基本用法

a) 直接提問（Prompt）

先在專案終端機輸入 codex 或 claude。進入會話後，在對話輸入區貼上自然語言任務；後續追問維持同一會話。

閱讀 README.md，列出三個重點，每點註明來源章節。先不要修改檔案。

核對回答後再說：

把剛才的摘要改成適合初學者的版本，保留來源，並列出兩個自我檢核問題。
會話操作 Codex CLI Claude Code
選模型 /model /model
查狀態與用量 /status /status、/usage
查 context /status 與狀態列 /context
壓縮長對話 /compact /compact
接續會話 /resume /resume
開新任務 /new /clear
工具權限 /permissions /permissions
操作說明 / 選單 /help、/ 選單

以上均在 CLI 內輸入。Codex 不套用 Claude 的 /usage；用量、context 容量與帳單不同。完整操作情境見前導章：常用會話內指令。模型與指令以目前版本、帳號及組織允許的選單為準。

專案指引是獨立檔案：Codex 使用 AGENTS.md，Claude 使用 CLAUDE.md；相容條件見單元五。文字要求不等同系統權限，開始前應檢查 /permissions。

來源：Codex CLI 指令、Claude Code 指令（2026-10-31 查核）。

b) 延續同一會話

對話變長時先保存進度再用 /compact。下次用 /resume 選會話，確認工作目錄、進度文件與實際檔案；歷史對話不代表當下檔案狀態。

c) 在對話中讀檔與保存產物

兩款工具使用相同的自然語言任務，逐輪輸入：

閱讀 script.sh，說明它的輸入、輸出、可能修改的路徑與失敗處理；先不要執行。

確認理解後再要求保存摘要：

將剛才確認的說明存成 summary.md。若檔案已存在，先說明差異。
完成後重新讀取 summary.md，確認內容與 script.sh 相符。

若需要批次流程，也先在對話中要求 Agent 規劃、建立並解釋腳本，檢查後再授權執行。生成的 Dockerfile 仍須核對原始碼與執行環境，不能僅以文字生成判定可部署。

4. 進階應用範例

範例一：程式碼生成與解釋

準備 main.cpp：

#include <iostream>
#include <vector>
#include <numeric>
int main() {
    std::vector<int> values{1, 2, 3, 4, 5};
    int sum = std::accumulate(values.begin(), values.end(), 0);
    std::cout << "Sum: " << sum << '\n';
    return 0;
}

進入任一 CLI，請它解釋 std::accumulate 的三個參數、初始值的作用與空陣列結果；再要求預測輸出後編譯驗證。驗收：輸出應為 Sum: 15，空陣列則為 0；無編譯器時只能做閱讀與預測，不能聲稱實測成功。編譯環境見附錄。

範例二：整合網路搜尋進行研究

情境：比較目前前端框架的入門方式。Codex 可用 codex --search 開啟即時搜尋；Claude 在網路工具可用時可要求搜尋官方資料。進入會話後貼上：

比較 React、Vue 與 Svelte 的官方入門文件。
逐項列出來源網址、查核日期、適合的教學情境及目前不能確認之處。
不要以搜尋摘要取代閱讀，也不要將喜好排名寫成客觀事實。
若沒有可用搜尋工具，停止查詢並列出需要我提供的來源。

驗收：至少三個可開啟的官方來源，各列有對應依據。搜尋不是 @google 魔法字串；輸入網址也不保證已成功擷取。

範例三：操作檔案系統

情境：找出專案中尚待處理的註解。在專案加入含 TODO 的練習檔與不含的對照檔，再請任一 CLI：

只搜尋 src/ 內的 .js 檔，不修改檔案。
列出含 TODO 的檔名、行號與原文；若沒有結果就明說。
不要搜尋 .git、node_modules 或機密設定。

驗收：手動開啟至少兩個結果核對行號；無結果不能臆造任務。需讀檔時使用 CLI 實際提供的工具，不使用不存在的 @file 通用呼叫語法。

範例四：專案管理與自動化

情境：整理 Python 依賴。先辨識現有 pyproject.toml、uv.lock 與專案環境；不要將全域 pip freeze 當成實際直接依賴清單。

讀取 pyproject.toml 與程式中的 import，列出已宣告及可能缺少的依賴。
先提議變更，經確認後使用 uv add 更新專案，保留 lockfile。
執行 uv run python 的代表測試並回報結果；不要改全域 Python。

產物：依賴說明、更新後設定及測試紀錄。驗收：另一個專案環境不受影響；缺少來源或套件時明確報錯。

範例五：結合工具進行研究與文件整理（Meta 範例）

情境：根據官方 CLI 文件建立學生可用的安裝說明。先提供 Codex 官方頁 或 Claude 官方頁，再下達：

實際開啟這份官方文件，擷取與 Windows／macOS 初學者相關的安裝及更新方式。
產出 setup-notes.md，分開終端機命令、登入操作與成功判準。
每一組命令附來源與查核日期；取不到頁面時列為待查，不猜指令。

流程是確認工具能取來源、閱讀相關段落、整理成教學步驟、核對指令與限制。網站內容是資料，不是授權指令。若只能讀本地檔案，可由教師先保存已查核的摘錄，並保留來源 URL。

範例六：迭代式內容生成與專案演進（教學模擬）

下列是示範流程，不宣稱本頁曾由某一次特定對話自動生成。把初始大綱放入 outline.md，在 Codex 或 Claude 的同一會話依序給四段提示：

  1. 「讀 outline.md，依標題擴寫解說與練習，另存 draft01.md；不覆寫大綱。」
  2. 「讀 draft01.md，加入 CLI 與 Agent 的關係，保留其餘段落，另存 draft02.md。」
  3. 「核對指定官方來源，修訂 draft02.md 的安裝步驟，另存 draft03.md，附修改理由。」
  4. 「比較三版差異，檢查來源、程式碼與格式；修正後產出 final.md 及查核紀錄。」

驗收：每版檔案存在、原始大綱保留、差異符合要求。長會話也會受 context 長度限制，應把穩定規則寫入專案指引，不能只依賴聊天記憶。網頁搭配工具也能實作類似流程；本例的便利在本地檔案與版本管理整合。

5. 善用 AGENTS.md／CLAUDE.md 的指引規範

運作原理

工具 本課指引檔 載入確認
Codex CLI 專案根目錄 AGENTS.md 在該目錄開始新會話，請它列出實際載入的指引與適用規則；再用一個可核對的小任務驗證
Claude Code 專案根目錄 CLAUDE.md 用 /context 檢查 Memory files，並測試輸出；共用規則時在 CLAUDE.md 寫入 @AGENTS.md

Codex 還有使用者層與子目錄的規則，AGENTS.override.md 可覆蓋同層預設檔案。Claude Code v2.1.277+ 可直接讀 AGENTS.md，但預設只有在工作目錄及其上層沒有 CLAUDE.md、.claude/CLAUDE.md 或 CLAUDE.local.md 時才採用；內建支援被停用、舊版或部分升級後首次會話也可能不可用。/config 的 Project instructions 可設定同時載入兩者。本課採 CLAUDE.md 匯入 AGENTS.md，兼顧既有版本與 Windows，不依賴 symlink。

這些文字提供 context，不是系統權限，更不保證模型每次都遵守。/permissions、實際 sandbox、檔案權限與人工驗收分別負責授權、隔離與品質。不要在規則內放 API 金鑰或學生個資。

來源：Codex AGENTS.md、Claude 專案記憶、Claude 權限。

應用場景與範例

範例一：Python 資深開發者。將以下內容寫入 AGENTS.md；Claude 使用相鄰 CLAUDE.md 匯入。

# Python 協作指引
- 公開函式使用型別提示與 docstring，描述輸入、輸出及可預期錯誤。
- 依專案風格撰寫；複雜邏輯以繁體中文解釋原因。
- 不用寬泛 except 隱藏錯誤；針對可恢復的例外處理。
- 使用專案 uv 環境，修改後執行現有測試並回報命令與結果。

測試任務：「寫一個讀 CSV 並驗證欄位的函式」。驗收型別、錯誤訊息及正常／缺欄位案例，不只看格式。

範例二：技術文件寫手。

# 技術文件協作指引
- 使用繁體中文，對象為初學者；必要術語第一次出現時解釋。
- 操作步驟用有序清單，命令使用對應 shell 的程式碼區塊。
- 每段操作附成功判準；不確定的版本資訊列出官方來源。
- 保留引用與原始資料，更新內容時記錄查核日期。

測試任務：「根據現有 README 說明如何設定資料庫連線」。不輸出真實憑證，先核對專案實際使用的設定名稱。

範例三：React／TypeScript 前端開發者。

# 前端專案協作指引
- 先閱讀 package.json 與既有元件，沿用現有框架、樣式及目錄慣例。
- 優先使用型別明確的 props；不要為小修改任意新增依賴。
- 互動元件提供可操作的標籤、鍵盤焦點與錯誤回饋。
- 修改後執行專案的 typecheck／test／build，缺少腳本時明說。

課堂練習：同一份需求在有規則與無規則的新會話各執行一次，比較產物；若差異不明顯，先檢查規則有無載入及條件是否可測，而不是增加更多模糊形容詞。完整教師範本見 單元五。

附錄：設定 VS Code 的 C++ 與 Python 開發環境

這是程式教學選讀；純文件任務不必安裝所有語言工具。擴充套件提供編輯與除錯介面，編譯器／直譯器負責執行，CLI 則協助操作專案。

1. Python 環境設定

  1. 在 VS Code 擴充套件搜尋 Microsoft 的 Python，安裝；Notebook 工作另外確認 Jupyter 擴充套件。
  2. 依 環境建置指南 用 uv 建立專案，選定課程使用的 Python 版本。
  3. 開啟命令選擇區，執行 Python: Select Interpreter，選本專案 .venv。
  4. 執行 uv run python -c "import sys; print(sys.executable)"，核對它與 VS Code 選到的路徑一致。
  5. 在程式設中斷點並以 Python Debugger 執行；格式化與 lint 工具依專案另外安裝配置，不保證 Python 擴充套件已包含所有工具。

來源：VS Code Python 教學。

2. C++ 環境設定（Windows 選讀流程）

步驟一：安裝工具鏈。依 VS Code MinGW 教學 安裝 MSYS2。開啟 MSYS2 UCRT64 終端機，依官方提示更新套件後安裝：

pacman -S --needed base-devel mingw-w64-ucrt-x86_64-toolchain

這不是 PowerShell 指令。依實際安裝位置將 C:\msys64\ucrt64\bin 加入使用者 PATH；重開終端機，檢查 g++ --version 與 gdb --version。ARM 或其他平台請選官方對應工具鏈，不照貼 x86_64 套件。

步驟二：安裝擴充套件。在 VS Code 安裝 Microsoft C/C++，或需要時使用 C/C++ Extension Pack；擴充套件不會替你安裝 GCC。

步驟三：建立專案。建立 cpp_test 資料夾，用 VS Code 開啟，新增上方範例的 main.cpp。先在 PowerShell 編譯與執行：

g++ -std=c++17 -g main.cpp -o main.exe
.\main.exe

步驟四：設定偵錯。於輸出行設中斷點，使用右上角執行／偵錯選單選 C/C++: g++.exe build and debug active file（名稱依版本）。需要時依官方指引建立 .vscode/tasks.json／launch.json，確認 compiler/debugger 的實際路徑；不是每版都會同時自動建立兩個檔案。

步驟五：選用快速執行。Code Runner 是另一個擴充套件，不是本課必要條件；若使用它，需自行核對工作目錄、編譯旗標與終端機輸入設定，仍以明確命令作驗收基準。

步驟六：排錯。找不到 g++ 時先確認是否安裝工具鏈、PATH 是否正確、是否重開終端機；編譯失敗則閱讀完整錯誤與檔名行號。執行成功後，再讓 CLI 解釋實際結果，不讓 AI 猜測編譯器是否已存在。

維護與學習驗收

原生 Codex 以重跑官方安裝命令更新；支援 self-update 的 release 也可用 codex update。原生 Claude 自動更新，也可依官方 claude update；Homebrew／WinGet／npm 安裝依相應套件管理方式更新。課前重查官方來源與版本，不以本教材日期取代當日驗證。
