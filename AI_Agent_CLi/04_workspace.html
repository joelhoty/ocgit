雙 CLI 操作約定

先在專案資料夾的終端機輸入 codex 或 claude，啟動其中一款工具。進入 CLI 會話後，直接輸入本章的自然語言提示；同一任務逐輪追問，不必每次重新啟動工具。

輸入位置 要做的事 範例
終端機 shell 啟動一次 CLI，兩款擇一 codex 或 claude
CLI 會話輸入區 說明任務、來源與產物 閱讀 lesson.txt，整理三個重點並標示來源。
同一會話輸入區 依剛才結果追問與修改 把第二個重點改寫成適合國小五年級的說明。

專案指引檔：Codex 使用 AGENTS.md，Claude Code 使用 CLAUDE.md。這些是保存專案慣例的檔案；設定方式及相容條件見單元五。

需要切換模型、查看用量或管理 context 時，使用 CLI 介面；兩款工具的常用斜線指令與差異見前導章。寫檔前說清楚路徑與是否保留原稿，完成後在 VS Code 開啟產物核對。自然語言的「不要修改」是任務要求，不能取代權限設定。

單元目標

  • 區分「網頁介面」、「本機工具執行」與「模型推論位置」
  • 學會先列出檔案、指定讀取範圍，再交代多檔案任務
  • 能夠讓 Agent 交叉整理多個檔案，並核對它實際讀了什麼
  • 掌握終端機 Agent 工作流程的優勢與應用

核心概念詳解

1. 網頁對話與終端機 Agent

兩者使用的都是雲端模型，差別在於工具在哪裡執行，以及檔案如何交給模型。

網頁對話 (如 網頁 AI、NotebookLM)

檔案如何交給模型：由您上傳、貼上或透過連接器提供，工具在服務商的環境執行。

特點：
- ✅ 操作簡單,打開瀏覽器就能用
- ✅ 通常可用瀏覽器操作，仍有帳號、地區與組織限制
- ⚠️ 透過上傳或連接器提供檔案，能力依介面而異

終端機 Agent (如 Codex CLI／Claude Code + VSCode)

檔案如何交給模型：工具在您的電腦上執行，依任務讀取資料夾內的檔案，再把讀到的內容送到雲端模型。

特點：
- ✅ 可直接讀取資料夾內的檔案
- ✅ 整合工作流程,效率更高
- ✅ 個人化設定（Codex：AGENTS.md；Claude Code：CLAUDE.md）
- ⚠️ 需要安裝設定(初次較複雜)
- ⚠️ 需要基本的電腦操作能力

兩者共通：都需要網路連線，內容都會經過網路傳到模型服務。工具在本機執行不代表資料留在本機。

2. 多檔案工作時差在哪裡？

情境 1：備課資料分散在多個檔案

網頁對話：
- 找到檔案 A → 複製內容 → 貼到 網頁 AI
- 找到檔案 B → 複製內容 → 貼到 網頁 AI
- 找到檔案 C → ...
- ❌ 繁瑣、容易遺漏

終端機 Agent：
- 在包含所有檔案的資料夾中開啟 VSCode
- 先請 Agent 列出檔案，再指定要讀哪些：「先列出這個資料夾的檔案，不要修改。接著閱讀 monday_lesson.txt 與 friday_test.txt，整理重點。」
- ✅ 範圍明確，也能核對 Agent 實際讀了哪些檔案

檔案存在硬碟上，不等於模型已經讀取；要求讀取整個資料夾也會占用 context。所以先列清單，再指定本輪要讀的檔案。

情境 2：需要重複使用的指令

網頁對話：
- 每次都要重新輸入完整的提示詞
- 容易遺忘之前好用的指令

終端機 Agent：
- 在專案指引（Codex 為 AGENTS.md，Claude 為 CLAUDE.md）中設定好「角色」與「預設指令」
- Agent 會依工具規則載入指引；仍需檢查實際輸出與權限

3. 終端機 Agent 工作環境的三個核心工具

graph LR A[VSCode<br/>工作環境] --> B[Terminal<br/>終端機] B --> C[Codex CLI／Claude Code<br/>AI 對話工具] C --> D[讀取本機檔案] D --> E[生成結果]
工具 功能 比喻
VSCode 整合式編輯器,可檢視檔案、執行指令 您的工作桌,所有工具都在這裡
Terminal (終端機) 輸入文字指令的地方 對電腦下達命令的「對講機」
Codex CLI／Claude Code 在終端機中與 AI 對話的工具 能讀檔、改檔，但要由您核對結果的助手

詳細操作步驟

本章假設您已能用 VS Code 開啟資料夾，並在整合終端機啟動 codex 或 claude。還不熟悉時，請先看前導章的 VS Code 工作台與第一次對話的共同驗證。以下範例都在同一個會話中進行。

步驟一：先確認 Agent 能讀到檔案

前提：資料夾中有一個 lesson.txt 檔案

請摘要 lesson.txt 這個檔案的內容

✅ 請確認工具紀錄真的讀取 lesson.txt，再核對摘要；沒有讀取成功時先修正路徑或權限。

步驟二：理解工作流程

graph TD A[在 VSCode 開啟專案資料夾] --> B[檢視檔案內容] B --> C[啟動 CLI 並輸入自然語言提示] C --> D[Agent 透過工具讀取檔案] D --> E[生成回應] E --> F{滿意嗎?} F -->|不滿意| H[同一會話追問與修改] H --> D F -->|滿意| G[複製結果或儲存]

跨學科應用範例

📐 數學科

情境：整理一週的教學檔案

資料夾結構：

math_week1/
  ├── monday_lesson.txt
  ├── wednesday_lesson.txt
  ├── friday_test.txt
  └── student_errors.txt

對話提示 1 - 全週摘要：

請先列出這個資料夾的檔案,不要修改。接著閱讀 monday_lesson.txt、wednesday_lesson.txt 與 friday_test.txt,整理出本週數學課的教學重點

對話提示 2 - 學生錯誤分析：

根據 student_errors.txt,分析學生最常犯的 3 個錯誤,並建議補救教學策略

對話提示 3 - 下週規劃：

根據本週教學內容與學生錯誤,建議下週的教學重點與活動

🌱 自然科

情境：實驗報告批改

資料夾結構：

science_experiment/
  ├── experiment_guide.txt (實驗說明)
  ├── student_report_1.txt
  ├── student_report_2.txt
  └── rubric.txt (評分標準)

對話提示 1 - 對照檢查：

根據 experiment_guide.txt 和 rubric.txt,檢查 student_report_1.txt 是否符合要求,列出優點與需改進之處

對話提示 2 - 批次分析 (如果有多份報告)：

請先列出這個資料夾中的 student_report 檔案,再逐份閱讀,歸納出學生普遍做得好的地方,以及共同的問題

🌍 社會科

情境：教材資料整合

資料夾結構：

history_unit/
  ├── textbook_chapter.txt (課本內容)
  ├── reference_article.txt (參考文章)
  ├── timeline.txt (時間軸)
  └── my_notes.txt (個人筆記)

對話提示 - 整合摘要：

請先列出這個資料夾的檔案。接著閱讀 textbook_chapter.txt、reference_article.txt、timeline.txt 與 my_notes.txt,製作一份完整的教學重點摘要,包含：1. 時間軸 2. 重要事件 3. 關鍵人物 4. 教學重點

📖 國語科

情境：作文批改輔助

資料夾結構：

writing_class/
  ├── topic.txt (作文題目與要求)
  ├── essay_A.txt
  ├── essay_B.txt
  └── scoring_guide.txt (評分標準)

對話提示：

根據 topic.txt 和 scoring_guide.txt,評析 essay_A.txt,提供具體的優點與改進建議,語氣要鼓勵而非批評

🌐 英語科

情境：課程資料準備

資料夾結構：

english_unit3/
  ├── vocabulary.txt (單字表)
  ├── dialogue.txt (課文對話)
  └── grammar_points.txt (文法重點)

對話提示 1 - 學習單生成：

請先列出這個資料夾的檔案。接著根據 vocabulary.txt、dialogue.txt 與 grammar_points.txt,設計一份學習單：包含 5 題單字填空、3 題文法選擇題、1 段對話填空

對話提示 2 - 課堂活動：

根據 dialogue.txt,設計一個 15 分鐘的角色扮演活動,包含角色分配、台詞提示、延伸問題

進階技巧

技巧 1：使用相對路徑指定檔案

情境：資料夾中檔案很多,只想讓 AI 看特定檔案

對話提示格式：

請根據 ./folder_name/file.txt 檔案,進行分析

範例：

請根據 ./lessons/week1.txt,摘要本週教學重點

技巧 2：輸出結果存檔

方法 1：複製貼上
- 選取終端機中 AI 的回應
- 使用終端機的「複製」功能或對應快捷鍵；避免把中斷執行的按鍵當成複製
- 貼到 Word 或其他文件

方法 2：在對話中請 Agent 儲存檔案

將剛才核對過的摘要內容整理好
請儲存為 output.txt；若已有同名檔案，先說明差異再詢問如何處理。

送出後檢查工具的寫檔紀錄，再到 VS Code 開啟 output.txt，確認檔案非空且內容與摘要一致。若沒有寫檔權限，先在 CLI 介面檢查授權，或手動複製保存。

技巧 3：多輪對話

在專案資料夾執行 codex 或 claude 啟動一次互動會話，以下三段是依次送出的提示，不是三次 shell 指令：

第一輪：請閱讀 lesson.txt，列出三個重點並引用原句。
第二輪：根據剛才的三個重點，設計三道附答案的題目。
第三輪：將剛才題目改為選擇題，列出每個錯誤選項對應的迷思。

若離開會話，可使用 CLI 的會話續接介面，先確認是同一專案。新開會話時請重新提供來源檔與工作摘要；同一會話也有 context 容量限制。長任務先保存已確認的決策，再用介面查看用量或整理 context；操作見前導章常用指令說明。

實用技巧與注意事項

✅ 終端機 Agent 最佳實踐

  1. 資料夾組織清楚：用有意義的資料夾名稱與檔案名稱
  2. 善用純文字檔：.txt 或 .md 檔案,AI 最容易讀取
  3. 一次處理一個專案：在 VSCode 中開啟該專案資料夾
  4. 檔案不要太大：檔案過大時先拆分
  5. 確認檔案路徑：檔案要在開啟的資料夾中,AI 才找得到

⚠️ 常見問題與排除

問題 可能原因 解決方式
輸入 codex 或 claude 指令無反應 CLI 未安裝或未設定 請檢查安裝步驟,確認指令可用
AI 說找不到檔案 檔案不在當前資料夾 確認 VSCode 開啟的是正確的資料夾
回應速度很慢 網路問題或檔案太大 檢查網路連線,或拆分檔案
CLI 會話無法輸入中文 輸入法、終端機或貼上設定問題 先在 VS Code 編輯區測試中文，再貼到 CLI 對話輸入區；確認輸入法與終端機設定

🎯 隱私與安全提醒

  1. 避免上傳敏感資料：不要讓 AI 讀取包含學生個資、成績的檔案
  2. 檔案備份：重要檔案先備份再操作
  3. 檢查輸出內容：AI 生成的內容仍需人工審核
  4. 了解資料流向：Codex CLI／Claude Code 通常會把提示與所讀內容送到所選服務商處理；實際資料政策依帳號與服務設定確認

本章範例中的學生檔案（如 student_errors.txt、student_report_1.txt、essay_A.txt）全部是虛構資料。

延伸應用

應用 1：建立個人教材庫

長期規劃：
1. 建立清晰的資料夾結構
2. 將教材轉成文字檔存放
3. 使用 AI 快速查找與摘要
4. 定期更新與整理

範例結構：

teaching_materials/
  ├── math/
  │   ├── grade5/
  │   │   ├── unit1/
  │   │   └── unit2/
  │   └── grade6/
  ├── science/
  └── social/

應用 2：學生作品分析

情境：收集學生反思日記,分析學習狀況

步驟：
1. 將學生日記存成獨立文字檔 (去識別化)
2. 放入同一資料夾
3. 用 AI 分析整體趨勢

對話提示：

請先列出這個資料夾的學生反思日記檔名,再逐份閱讀,歸納出：1. 學生覺得最困難的部分 2. 最有成就感的部分 3. 共同的疑問

應用 3：快速產生變化版本

情境：同一份教材,需要不同難度版本

步驟：
1. 原始教材存成 original.txt
2. 在 CLI 會話中說明三個版本的對象與難度

對話提示範例：

將 original.txt 改寫成三個版本：1. 簡化版(國小三年級) 2. 標準版(國小五年級) 3. 進階版(國中程度),分別輸出

練習任務

初階任務

  1. 建立一個含 2-3 個 .txt 檔案的資料夾，用 VS Code 開啟並啟動 codex 或 claude
  2. 請 Agent 先列出檔案，不要修改
  3. 指定其中一個檔案請 AI 摘要，再回到原檔核對

進階任務

  1. 建立一個教學專案資料夾,包含 3-5 個檔案
  2. 在同一會話請 AI 列出讀檔清單，再分析整個資料夾
  3. 追問修改，再請 AI 將核對過的內容保存成教案；開啟產物驗收

常見問題 Q&A

Q1：我不懂程式設計,可以學會這個嗎？
A1：可以。先學會啟動 CLI，再用自然語言說明任務、來源與預期結果；讀檔和修改仍要檢查工具紀錄與實際產物。

Q2：VSCode 會不會很難學？
A2：我們只用到最基本的功能：檢視檔案 + 開啟終端機。不需要學習複雜的編輯功能。

Q3：如果提示說錯怎麼辦？
A3：在同一會話補充或更正要求。若已改動檔案，先檢查修改差異，再請 Agent 修正；重要檔案用 Git 或備份保留可回復版本。

Q4：一定要用 VSCode 嗎？可以用其他工具嗎？
A4：VSCode 是建議工具,因為它整合了編輯器與終端機。如果熟悉其他工具 (如 Terminal app),也可以使用。

Q5：這樣使用需要付費嗎？
A5：VS Code 可免費使用；CLI 模型服務的帳號資格、額度與 API 計費依服務方案而異。授課前依前導章官方連結確認，不把安裝免費等同模型使用免費。

Q6：我的檔案是 Word 或 PDF,AI 可以讀取嗎？
A6：可讀格式取決於會話工具；本課先轉成 .txt 或 .md 並人工核對。掃描 PDF 需 OCR，DOCX 的圖片、表格與頁碼轉換後可能遺失，不能假設已完整讀取。

Q7：跟單元一的提示詞練習有什麼不同？
A7：單元一先學如何交代任務；這裡再學工作目錄、讀檔與輸出驗證。兩者使用同一套提示原則。

小結：讓 Agent 在您指定的資料夾內工作,它就能交叉整理多個檔案並寫回結果。透過 VSCode + Codex CLI／Claude Code,您可以更高效地處理教學資料、分析學生作品、準備教材；模型仍在雲端,所以要清楚指定讀取範圍,並核對實際產物。初期需要一點學習,但熟悉後會發現效率大幅提升！

準備 lesson.txt（三段自寫教材）與 criteria.md（三個重點、每點一個來源原句）。在任一 CLI 會話要求產生 summary.md。完成時核對：工作目錄正確、讀檔紀錄成功、三個原句可在來源找到、原始檔未被修改。這些證據比 AI 自稱「已讀取」更可靠。
