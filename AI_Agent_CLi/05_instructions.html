單元目標

  • 理解 AGENTS.md 與 CLAUDE.md 的功能、作用範圍與載入差異
  • 學會撰寫基本的 AI 角色設定
  • 能夠客製化 AI 的回應風格與工作流程
  • 掌握從通用 AI 到專屬助理的設定技巧

核心概念詳解

1. AGENTS.md／CLAUDE.md 是什麼？

核心比喻：AGENTS.md 就像是您為 AI 助理撰寫的「員工手冊」或「角色設定卡」。

沒有 AGENTS.md 的 AI

  • 像臨時工：每次都要重新說明要做什麼
  • 不了解您的習慣與需求
  • 回答方式可能不符合預期

有 AGENTS.md 的 AI

  • 像正職員工：已接受培訓,知道工作流程
  • 理解您的角色需求與偏好
  • 將已載入規則作為工作依據；仍需驗證是否遵循

2. AGENTS.md 可以設定什麼？

設定類型 說明 範例
角色定位 AI 應扮演什麼角色 「你是一位國小數學老師」
說話風格 語氣、用詞、長度 「回答簡潔、親切、避免術語」
工作流程 固定的處理步驟 「收到教材後,先摘要再出題」
輸出格式 回應的呈現方式 「用條列式,每點不超過 50 字」
限制與規則 不該做的事 「不使用艱深術語」

3. AGENTS.md 的運作原理

graph LR A[您下達指令] --> B[CLI 載入適用專案指引] B --> C[將角色設定傳給 AI] C --> D[AI 根據設定生成回應] D --> E[輸出結果]

關鍵：啟動目錄、工具版本與規則層級決定載入內容，不是只要檔案存在就一定生效。修改規則後，以新會話重新核對。

工具 本課指引檔 載入確認
Codex CLI 專案根目錄 AGENTS.md 在該目錄開始新會話，請它列出實際載入的指引與適用規則；再用一個可核對的小任務驗證
Claude Code 專案根目錄 CLAUDE.md 用 /context 檢查 Memory files，並測試輸出；共用規則時在 CLAUDE.md 寫入 @AGENTS.md

Codex 還有使用者層與子目錄的規則，AGENTS.override.md 可覆蓋同層預設檔案。Claude Code v2.1.277+ 可直接讀 AGENTS.md，但預設只有在工作目錄及其上層沒有 CLAUDE.md、.claude/CLAUDE.md 或 CLAUDE.local.md 時才採用；內建支援被停用、舊版或部分升級後首次會話也可能不可用。/config 的 Project instructions 可設定同時載入兩者。本課採 CLAUDE.md 匯入 AGENTS.md，兼顧既有版本與 Windows，不依賴 symlink。

這些文字提供 context，不是系統權限，更不保證模型每次都遵守。/permissions、實際 sandbox、檔案權限與人工驗收分別負責授權、隔離與品質。不要在規則內放 API 金鑰或學生個資。

來源：Codex AGENTS.md、Claude 專案記憶、Claude 權限。

詳細操作步驟

您可能已經依前導章的專案指引建立規則檔；本單元在那個基礎上延伸。

步驟一：建立 AGENTS.md 檔案

方法 1：在 VSCode 中建立

  1. 在 VSCode 左側檔案總管中,點選右鍵
  2. 選擇「新增檔案」(New File)
  3. Codex 的共用規則檔名輸入：AGENTS.md（注意大寫）
  4. 按下 Enter

方法 2：在終端機建立

macOS／Linux／WSL：

touch AGENTS.md

Windows PowerShell（先確認沒有同名檔案）：

New-Item -ItemType File -Path AGENTS.md

Claude Code：在同一層用 VS Code 新增 CLAUDE.md，寫入下列內容。這是檔案內容，不是終端機命令：

@AGENTS.md

這樣共用範本仍只維護在 AGENTS.md；Claude 專屬補充可寫在匯入行下方。不要同時手動複製兩份長規則而忘記同步。

步驟二：撰寫基本的 AGENTS.md

最簡範本

# AI 角色設定

你是一位經驗豐富的國小老師。

## 說話風格
- 語氣親切、鼓勵
- 用詞簡單易懂
- 避免艱深術語

## 回應原則
- 回答簡潔,每段不超過 100 字
- 使用條列式呈現重點
- 適時舉例說明

重點說明：
- # 開頭是標題,幫助組織內容
- 清楚說明角色、風格、原則
- 使用 Markdown 格式(條列、標題等)

步驟三：測試 AGENTS.md 是否生效

測試指令

在專案根目錄啟動其中一款工具：

codex
# 或選用：claude

在 AI 會話貼上（不是 shell 命令）：

列出本次已載入的專案指引及適用規則。
用國小五年級能理解的方式說明分數，每段不超過 100 字。
只回覆，不修改檔案；指出任何互相矛盾或未讀取的規則。

Claude 用 /context 確認實際載入的 Memory files；Codex 在新會話確認工作目錄與適用指引，再核對實際產物。/memory 也會列出不存在的檔案，不能當成載入證明；要用它直接確認 AGENTS.md，需要 v2.1.280 以上。

預期結果：
輸出應符合角色、每段字數與條列格式。核對載入紀錄及實際結果；自我介紹不等於規則已生效，正確回覆一次也不保證所有任務都正確。

比較：
- 未設定 AGENTS.md：回答可能較正式、通用
- 已設定 AGENTS.md：回答符合您的角色設定

步驟四：修改與調整

  1. 在 VSCode 中開啟 AGENTS.md
  2. 編輯內容(例如:改變角色、調整風格)
  3. 儲存檔案 (Ctrl+S / Cmd+S)
  4. 結束原會話，從同一專案目錄啟動新會話，以相同測試核對變化
  5. 查看 Git 差異，確保只改了指定規則；記錄版本、測試提示與觀察結果

跨學科 AGENTS.md／CLAUDE.md 範本

以下數學、自然、社會、語文等範本可保留原內容放在 AGENTS.md，再由 CLAUDE.md 匯入。規則不會替代實際教材來源，也不會讓 AI 自動取得某個年級的正式課綱；請另提供授課依據。

請把這些範本當成菜單，挑 3-5 條可以測試的規則使用，並像前導章的範例一樣補上來源與驗收規則，例如「來源沒寫的內容列為待查」「完成時列出檔案位置、檢查方式與尚未確認的事項」。

1. 先確認數學概念的核心

進階設定技巧

技巧 1：設定預設任務

情境：您經常需要 AI 將教材改寫成不同難度

AGENTS.md 設定：

## 預設任務模式

當我說「改寫」時,請自動產生三個版本:
- **簡化版**:適合學習較慢的學生,使用更簡單的詞彙
- **標準版**:符合課綱要求的難度
- **進階版**:適合學習快速的學生,加入延伸內容

每個版本請標示清楚,並說明調整重點。

使用方式：先啟動所選 CLI，在對話中輸入以下提示，並貼上原文或提供實際檔案位置。

依專案指引的「改寫」規則，將我提供的光合作用說明改寫為三種難度。

兩款工具共用這份自然語言提示。預期產生三個版本，再人工核對內容、難度與學習目標，不以篇幅判定品質。

情境：您需要固定格式的學習單

AGENTS.md 設定：

## 學習單輸出範本

當我要求「設計學習單」時,請使用以下格式:

---
**學習單標題**: [主題名稱]
**適用年級**: [年級]

[設計 1-2 個引導問題]

**第二部分:核心練習**
[設計 5-7 道題目,包含不同類型]

**第三部分:延伸思考**
[設計 1-2 個開放式問題]

**教師備註**: [教學提示或注意事項]
---

技巧 3：設定限制與禁止

AGENTS.md 設定：

## 限制與規則

請務必遵守以下原則:
- ❌ 不使用國中以上程度的專業術語
- ❌ 給學習者的內容不直接給答案；我要求答案時才提供
- ❌ 不使用消極或批評的語言
- ✅ 永遠保持鼓勵與正面的態度
- ✅ 遇到不確定的資訊,請明確說明
- ✅ 題目設計要有層次(簡單→困難)

技巧 4：多情境模式切換

這些「模式」是自己約定的提示前綴，不是 CLI 的權限模式；不會改變 sandbox 或工具許可。

情境：同一個檔案,想針對不同任務使用不同模式

AGENTS.md 設定：

## 工作模式

請根據我的指令前綴,切換對應模式:

### 模式 A:「快速模式」
- 目標:快速提供簡要資訊
- 回應:不超過 150 字
- 格式:條列式

### 模式 B:「深度模式」
- 目標:詳細分析與說明
- 回應:包含背景、分析、建議
- 格式:分段論述

### 模式 C:「出題模式」
- 目標:根據內容出題
- 類型:選擇、填空、簡答、討論
- 格式:題號清楚,附標準答案

使用方式：在已啟動的 CLI 會話輸入，兩款工具皆適用。

【快速模式】讀 inputs/lesson.md 並摘要；只回覆，不改檔。

這裡的「快速模式」是專案文件自訂的回應格式，不是 CLI 的模型或速度設定。若要換模型，使用會話內的 /model；常用指令見前導章。

實用技巧與注意事項

✅ AGENTS.md 撰寫最佳實踐

  1. 清晰的結構：使用標題、條列,方便閱讀
  2. 具體的描述：「親切」比「好」更明確
  3. 舉例說明：提供範例格式,AI 會模仿
  4. 持續優化：根據使用經驗調整
  5. 測試驗證：每次修改後測試效果

⚠️ 常見錯誤

錯誤 說明 正確做法
設定太籠統 「請表現專業」 「使用教育專業術語,語氣正式」
要求互相矛盾 「簡潔但詳細」 明確區分情境:快速摘要用簡潔,深度分析用詳細
過度複雜 設定太多規則,AI 難以遵循 聚焦 3-5 個核心設定即可
未測試就使用 寫完未確認是否生效 先用簡單指令測試

🎯 效果檢查清單

設定完成後,用以下問題檢驗：

  • [ ] 輸出符合角色設定嗎？(用詞、程度與任務範圍符合規則，不看自我介紹)
  • [ ] 回應的語氣符合設定嗎？(親切/正式/活潑)
  • [ ] 輸出格式符合預期嗎？(條列/段落/表格)
  • [ ] AI 遵守限制規則嗎？(不使用術語/給學習者的內容不直接給答案)
  • [ ] 整體表現提升了嗎？(比未設定更貼近需求)

延伸應用

應用 1：建立學科專屬 AI 助理

長期策略：
1. 為每個學科建立獨立資料夾
2. 每個資料夾放置專屬的 AGENTS.md
3. 在各資料夾啟動新會話，確認實際載入的規則；父層規則仍可能一起生效
4. Claude 在各學科資料夾使用 CLAUDE.md 匯入該處 AGENTS.md，避免版本支援差異

資料夾結構：

teaching/
  ├── math/
  │   ├── AGENTS.md (數學教師設定)
  │   └── materials/
  ├── science/
  │   ├── AGENTS.md (自然教師設定)
  │   └── materials/
  └── language/
      ├── AGENTS.md (國語教師設定)
      └── materials/

應用 2：團隊協作範本

情境：與同事共同備課,統一 AI 使用方式

做法：
1. 團隊共同制定 AGENTS.md 範本
2. 用共同測例比較產物風格與來源；有範本仍須驗收
3. 定期檢討與更新

好處：
- 教材風格統一
- 避免重複設定
- 累積團隊知識

練習任務

初階任務

  1. 建立您的第一個 AGENTS.md,設定基本的角色與風格
  2. 測試 AI 是否遵循設定
  3. 根據回應結果,調整設定

進階任務

  1. 為您任教的學科,設計完整的 AGENTS.md(包含角色、流程、格式)
  2. 設定至少兩種「工作模式」並測試切換
  3. 建立學科專屬的資料夾系統

常見問題 Q&A

Q1：指引檔一定要放在哪裡？
A1：本課把 AGENTS.md 與 CLAUDE.md 放在專案根目錄，並從該處啟動 CLI。Codex 與 Claude 也有使用者層及子目錄規則，不能把「VS Code 開啟的資料夾」當成唯一載入依據；先核對終端機工作目錄。

Q2：我可以有多個指引檔嗎？
A2：可以用根目錄共通規則搭配子目錄特定規則；但工具載入與優先順序不同。Codex 的 AGENTS.override.md 不等於 Claude 支援的檔名。先用一個根目錄檔完成練習，再增加層級。

Q3：規則會影響所有指令嗎？
A3：規則只影響讀到它的 AI 會話，不會改變你手動執行的 shell 命令，也不能覆蓋更高層政策或實際檔案權限。Claude 新版可直接支援 AGENTS.md，但受到前述版本、CLAUDE.md 存在與設定條件限制。

Q4：設定太多會不會讓 AI 混亂？
A4：過長、矛盾或無法驗證的規則會增加 context 負擔。先聚焦三到五項核心規則，把細節放到任務資料；以測例結果決定是否調整。

Q5：我可以臨時調整設定嗎？
A5：對可由任務調整的風格，可以明確寫「本次請詳細說明」。這不表示任意提示都能覆蓋系統、組織或安全限制；有衝突先釐清適用規則。

Q6：AI 沒有遵守設定怎麼辦？
A6：先檢查檔名大小寫、儲存、啟動目錄、上層及子層檔案。Claude 使用 /context 核對 Memory files，必要時用 CLAUDE.md 的 @AGENTS.md 匯入；Codex 開新會話再核對適用指引。確認規則可測且沒有矛盾，最後檢查實際產物，不只追問「你有讀嗎」。

Q7：可以參考其他人的指引檔嗎？
A7：可以，但要先閱讀每條規則、檢查外部連結與可能執行的工作流程。改成自己的年級、學科、來源與驗收條件；不要把陌生設定直接當成可信任的命令。

交付 AGENTS.md、CLAUDE.md（如選 Claude）、一段測試提示、實際回覆與檢查紀錄。至少核對角色、字數、來源及輸出位置四項；保留一個規則衝突或未載入的案例與修正方法。使用一款工具即可完成，雙工具比較列為進階練習。
