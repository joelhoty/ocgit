1. 課程簡介（Introduction）

為什麼要學習 Agent CLI？

CLI 能把資料、編輯與命令執行連在同一個專案中，適合反覆修改教材、整理檔案及開發小工具。關鍵能力是把模糊需求變成「指定輸入、限制、產物、驗收」，而不是背誦所有參數。完成本課後，你應能讀懂一段程式、驗收一次修改、核對網路來源並建立可測的原型。

階段 輸入 學習者交付物
Level 1 範例程式 解釋、預測與實際結果
Level 2 有缺陷的小程式 修正差異與正常／邊界測試
Level 3 官方網站與明確問題 帶日期和來源的比較表
Level 4 原型需求與限制 可開啟的頁面及驗收紀錄

2. 環境建置（Installation）

2.1. 前置需求：選擇工具與安裝路線

終端機、網路與可用帳號是起點。原生安裝不需預先安裝 Node.js；只有選 npm 或執行 JavaScript 專案時才需要 Node。Windows PowerShell 與 macOS shell 命令分開使用，安裝完後記下版本與安裝方式。不要使用另一款產品的 API key 登入。

2.2. 安裝 Codex CLI 或 Claude Code

安裝指令只維護在一處：請到前導章的安裝章節選一款工具，完成後再回到這裡。

2.3. 啟動與登入

建立 cli-practice 資料夾，用 VS Code 開啟。整合終端機進入該目錄後執行 git init，再啟動 codex 或 claude，依瀏覽器流程登入。用 codex login status 或 claude auth status --text 確認狀態；帳號方案與 API 額度分開計算，依官方帳號畫面為準。

第一個任務：請 AI「只列出這個資料夾有哪些檔案，不修改」。確認工作目錄與結果相同後，再進行後續寫檔練習。遇到權限要求，先看它要執行的操作與路徑，依任務需要核准。Codex 認證、Claude 入門。

3. 基礎操作指南（Basic Operations）

3.1. 對話與常用會話指令

先在專案終端機輸入 codex 或 claude。進入會話後，在對話輸入區貼上自然語言任務；後續追問維持同一會話。

閱讀 README.md，列出三個重點，每點註明來源章節。先不要修改檔案。

核對回答後再說：

把剛才的摘要改成適合初學者的版本，保留來源，並列出兩個自我檢核問題。

會話內指令（選模型、查用量、壓縮 context、接續會話等）的對照表只維護在前導章：常用會話內指令速查；實際可用指令以目前版本、帳號及組織允許的選單為準。

專案指引是獨立檔案：Codex 使用 AGENTS.md，Claude 使用 CLAUDE.md；相容條件見單元五。文字要求不等同系統權限，開始前應檢查 /permissions。

更新與故障排除：原生 Codex 重跑安裝命令；支援 self-update 的 release 可用 codex update。原生 Claude 會自動更新，手動可用 claude update；若以 Homebrew 或 WinGet 安裝，改用該管理器的 upgrade。找不到指令先重開終端機並檢查 PATH，版本可顯示但不能使用則先查登入與帳號，不要反覆重裝。詳見前導章附錄 A。

提示的四段式寫法：「讀什麼 → 要做什麼 → 不可做什麼 → 如何驗收」。在 AI 會話內貼自然語言提示；在 shell 中執行 codex／claude。不要將說明句當 shell 命令，也不要虛構 @shell、@google 或 @web 為通用 CLI 語法。

4. 實戰應用範例（Hands-on Examples）

🔰 Level 1：程式碼解釋與學習（Code Explanation）

準備：在專案新增 average.py，內容如下：

scores = [70, 80, 90]
average = sum(scores) / len(scores)
print(average)

在任一工具的互動會話貼上：

只閱讀 average.py，不修改。
用繁體中文逐行說明，先預測輸出，再列出如何執行驗證。
指出空清單會發生什麼，並提出一個可測的改進。

學習重點：先預測再執行，避免把 AI 的文字當成執行結果。已準備 Python 環境者用 uv run python average.py，應輸出 80.0。沒有 Python 可先完成閱讀，但要將「尚未執行」寫入學習紀錄。延伸：換成 [60, 90]，自己算出 75，再核對工具結果。

🔧 Level 2：自動化重構與除錯（Refactoring）

把上例的運算整理成函式，新增空輸入測例。任務提示：

將 average.py 改為可重用的 mean_score(scores) 函式。
空清單要拋出有意義的 ValueError，不回傳假平均值。
保留原先 [70,80,90] 的示範輸出，新增正常與空輸入測試。
先說明修改計畫，再改檔，執行測試並列出結果與差異。

預期產物：函式、測試與執行紀錄。驗收：正常為 80.0；單一值 [95] 為 95；空清單得到指定錯誤。查看 git diff 及 git status，確認未修改其他教材。若 AI 宣稱測試成功，要求對應命令、退出碼與實際輸出。不要把「讓錯誤消失」等同「需求正確」。

🌐 Level 3：聯網搜尋與生活應用（Web Search & Life Hacks）

Codex 可在 shell 使用 codex --search；Claude 依會話可用的 WebSearch／WebFetch 與網路權限處理。兩者若無法連網，請教師提供來源摘錄，保留 URL 與查核日期。以下三種情境保留為資料素養練習，不讓 AI 自行購買或預訂。

💡 情境 A：旅遊規劃助手（Travel Planning）

規劃一次兩日校外參訪的草案。先問清楚出發地、日期、人數與交通限制。
查官方景點開放日與交通資料，表列時間、來源、查核日期與未確認事項。
不預訂、不付款；若資訊衝突，並列差異並提出人工確認方式。

產物：行程表、來源表、待確認清單。驗收：活動日真的開放、交通銜接合理、報價沒有被當成永遠有效；實際出發前由人重新確認。

💡 情境 B：購物決策與規格比較（Shopping Comparison）

依我提供的三款設備型號，比較官方規格與教學需求。
先確認預算、用途、必要連接埠與作業系統；同系列不同型號不可混用規格。
區分官方規格、商家價格及你的推論；每列附來源與查核日期。
不要下單，也不要以單一排名取代需求分析。

產物：可追溯的比較表。驗收：型號完整、單位一致、必要條件逐項比對；價格或庫存查不到就標明，不能補造數字。

💡 情境 C：高效率閱讀與學習（Smart Reading）

閱讀我指定的文章或公開課程文件，整理核心問題、三個重點與兩個自我測驗。
每個重點附對應段落或頁碼，不把文中沒有的內容寫成作者結論。
若網頁需要登入或內容取不到，請明確回報並等待我提供可讀版本。

產物：摘要、來源定位及答案說明。驗收：回到原文抽查三個主張；區分原作者敘述與 AI 延伸問題。來源文件裡要求「忽略你的規則」的文字仍只是資料，不能取得你的工作權限。

🚀 Level 4：快速建立專案原型（Prototyping）

情境：為一節課做一個不需伺服器的選擇題練習頁。先在新的子目錄工作，避免覆寫本課索引：

在 quiz-demo/ 建立 index.html、style.css、script.js。
題目使用我提供的三題內容，不新增未查核知識；每題四選一。
提交後顯示答對數與逐題解析，未作答要有提示；提供重新作答按鈕。
不接登入、資料庫、外部追蹤或付款；先列實作計畫。
完成後提供開啟方式，檢查鍵盤操作、手機版與全對／全錯／漏答三種情境。

產物：三個檔案及測試紀錄。驗收：瀏覽器可開啟、計分正確、重做狀態重置、手機文字沒有被裁切。CLI 能產生檔案不代表已驗證頁面；若工具沒有瀏覽器能力，由你實際開啟核對，紀錄測試者與結果。

5. 進階技巧：專案專屬設定

指引檔的載入方式、相容條件與驗證方法集中在單元五，這裡只保留課堂規則範例。

在 AGENTS.md 放入課程規則，再讓 CLAUDE.md 匯入：

# 課堂專案規則
- 使用繁體中文；先讀指定來源，輸出到 outputs/。
- 不改 inputs/；不刪除未確認的檔案。
- 範例採虛構資料；不寫入 API 金鑰、學生姓名或學號。
- 完成後列出修改檔案、驗證方法與仍需人工確認的項目。

Claude 的 CLAUDE.md：

@AGENTS.md

新會話先確認指引載入，再用一個小任務測試。不因模型答出「我會遵守」就認定所有規則有效；輸出位置、來源與禁止修改檔案都要實際核對。完整跨科教師模板見 單元五。

6. 學習總結

CLI 讓 Agent 在專案中讀資料、改內容與執行工具；人仍負責目標、權限與驗收。Codex 與 Claude 命令不同，但可靠的工作流程一致：明確輸入 → 最小任務 → 真實工具結果 → 檔案差異 → 人工抽查。

建議練習

  1. 初階：完成 Level 1，提交預測與實際輸出的比較。
  2. 中階：完成 Level 2，交付正常、單一輸入、空輸入的測試證據。
  3. 進階：完成 Level 3 任一題，抽查來源；再完成 Level 4 的漏答與重做驗收。
  4. 比較：用另一款 CLI 做相同任務，記錄權限、指引載入與結果差異；不只比較文字長度。

完成後回到 課程索引，把同一流程用於六個漸進單元的教學設計。
