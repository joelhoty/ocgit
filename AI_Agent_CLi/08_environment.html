第一部分：安裝 Codex CLI 或 Claude Code

1. 安裝前先分清楚依賴

CLI 原生安裝不需要先裝 Node.js。只有使用 npm 替代安裝或執行 JavaScript／部分 MCP 工具時，才另裝 Node。Python 與 uv 屬於後續 Python 專案的工具。請先確認 shell 類型、網路及帳號資格；Windows 以 PowerShell 開啟，macOS 以 Terminal 開啟。

可在 PowerShell 查看 $PSVersionTable.PSVersion。課程示例以 PowerShell 7 為主；Windows PowerShell 5.1 不支援所有相同語法與編碼預設。學校裝置若不允許安裝，依資訊人員提供的方式處理，勿自行變更全機執行原則。

2. 安裝與首次登入

系統／安裝方式 Codex CLI Claude Code
Windows PowerShell（新視窗） powershell -ExecutionPolicy Bypass -c "irm https://chatgpt.com/codex/install.ps1 | iex" irm https://claude.ai/install.ps1 | iex
macOS／Linux／WSL 終端機 curl -fsSL https://chatgpt.com/codex/install.sh | sh curl -fsSL https://claude.ai/install.sh | bash
macOS Homebrew（替代） brew install --cask codex brew install --cask claude-code
Windows WinGet（Claude 替代） 本課不列未查核的 CLI 套件名稱 winget install Anthropic.ClaudeCode

表格的 | 是管線字元。每款工具只選一種安裝方法，避免多份執行檔搶用 PATH。下載腳本會在本機執行；學校電腦請使用管理員核准的安裝路線。這些指令在 shell 執行，不貼到 AI 對話中。

安裝後重新開終端機，選所用工具檢查：

codex --version
# 或選 Claude Code：
claude --version

查核：2026-10-31。Codex 安裝、Windows CLI 部署、Claude Code 安裝。

在 VS Code 的「檔案 → 開啟資料夾」選一個練習專案，再開整合終端機。確認命令列位置後執行 codex 或 claude；依畫面用瀏覽器登入。安裝成功與登入成功要分別確認：版本號不代表帳號具有工具使用額度。

檢查／維護 Codex CLI Claude Code
版本 codex --version claude --version
登入狀態 codex login status claude auth status --text
重新登入 codex login claude auth login
原生更新 重跑官方安裝命令；支援的 release 可用 codex update 背景自動更新；claude update 可手動更新
安裝診斷 檢查 PATH、codex --help 與錯誤訊息 claude doctor

使用 Homebrew 時用 brew upgrade --cask codex 或 brew upgrade --cask claude-code；使用 WinGet 時用 winget upgrade Anthropic.ClaudeCode。npm 更新使用安裝套件的 @latest 路線。不要把 CLI 更新與專案套件更新混在一起。Codex 認證、Codex 命令、Claude CLI。

3. 常見問題排除：PowerShell、PATH 與權限

現象 先檢查 處理方向
找不到 codex／claude Get-Command codex 或 Get-Command claude 重開終端機，核對安裝目錄與使用者 PATH；不要重複裝多種版本
npm.ps1 被封鎖 是否真的選了 npm 路線 原生路線無須 npm；既有 npm 使用者可依組織核准方式或 npm.cmd 啟動，不全面放寬政策
irm 無法辨識 是否在 CMD 而非 PowerShell 回到對應 shell；不要任意互換 CMD 與 PowerShell 語法
安裝下載失敗 網路、代理、官方 URL 與錯誤碼 保存錯誤供資訊人員排查，勿以關閉安全工具作為通用解法
版本可顯示但請求失敗 登入、方案額度、組織權限 檢查帳號狀態；不要反覆重裝
工具要求核准／拒絕執行 實際權限與 sandbox 閱讀要求的目錄與命令，針對本次必要操作選擇權限

Codex 可原生運行於 Windows，沙箱依裝置支援與政策選擇。Claude Code 原生 Windows 目前沒有 Claude sandbox；WSL2 可提供相應沙箱。Git for Windows 在 Claude 原生 Windows 是推薦選項，未安裝時可使用 PowerShell 工具。CLI 權限提示與 OS 沙箱不是同一層。Codex Windows、Claude 平台差異。

第二部分：安裝與設定 Visual Studio Code（VS Code）

1. 下載與安裝

  1. 從 VS Code 官方網站 取得符合系統與 CPU 的版本。
  2. 安裝後開啟「檔案 → 開啟資料夾」，選本課專案。
  3. 用「終端機 → 新增終端機」開啟 shell；Windows 選 PowerShell，macOS 通常是 zsh。
  4. 檢查目前路徑：PowerShell 用 Get-Location，macOS 用 pwd。確認不是個人目錄或下載資料夾才開始工作。

編輯器負責檢視檔案與差異；整合終端機只是執行 shell 的位置。不需要先安裝 Codex 或 Claude 的 VS Code 擴充套件才能在終端機使用 CLI。

2. 安裝 Python 擴充套件

  1. 開啟 Extensions（Windows Ctrl+Shift+X；macOS Cmd+Shift+X）。
  2. 搜尋 Python，核對發布者為 Microsoft，再安裝。
  3. 需要 Notebook 時另確認 Jupyter 支援；格式化與 lint 工具按專案需求設定。
  4. 完成下一部分的 .venv 後，執行 Python: Select Interpreter 選取該環境。

擴充套件不等於 Python 本身。若右上角執行結果與 uv run 不同，先比較兩邊 sys.executable。VS Code Python 教學。

第三部分：Python 環境與 uv 套件管理（核心觀念）

1. 安裝 Python：由 uv 管理

本課使用 Python 3.13 作為可重現示例，不宣稱它是最新版本。可先安裝 uv，再用 uv python install 3.13 取得 Python；無須先手動安裝另一份 Python。若班級已固定其他受支援版本，請教師同步調整教材與測試。

2. 重要概念：什麼是虛擬環境（Virtual Environment）？

全域環境像所有專案共用的一箱工具；虛擬環境像每個專案自己的工具箱。A 專案需要的套件版本不必改動 B 專案。.venv 放執行環境，pyproject.toml 宣告專案與直接依賴，uv.lock 記錄解析後的版本。三者用途不同：只複製 .venv 不能保證跨電腦重現，也不應提交 .venv 到 Git。

注意：虛擬環境隔離 Python 套件，不隔離檔案存取或網路；它不是安全 sandbox。

3. 安裝 uv（Python 管理工具）

Windows PowerShell 可選 WinGet：

winget install --id=astral-sh.uv -e

macOS／Linux 官方獨立安裝方式：

curl -LsSf https://astral.sh/uv/install.sh | sh

重開終端機後執行 uv --version，看到版本號再繼續。安裝方式與更新方式對應：WinGet 用 winget upgrade --id=astral-sh.uv -e；獨立安裝版可用 uv self update。詳見 uv 安裝文件。

4. 實戰演練：使用 uv 建立 Python 專案（標準流程）

步驟 1：初始化專案

以下命令在 shell 逐行執行，先確認沒有同名既有專案：

uv python install 3.13
uv init --python 3.13 teaching-analysis
cd teaching-analysis

成功判準：目錄中有 pyproject.toml 與 .python-version。先看 uv init 顯示的檔案，不假設所有版本都產生相同示範程式。

步驟 2：建立虛擬環境

uv sync
uv run python -c "import sys; print(sys.version); print(sys.executable)"

成功判準：Python 為 3.13 系列，路徑指向本專案 .venv。不必先手動 activate 才能使用 uv run。在 VS Code 同步選取 .venv 直譯器。

步驟 3：安裝套件（Install Packages）

uv add pandas
uv run python -c "import pandas; print(pandas.__version__)"

uv add 會更新專案依賴紀錄。單純標準函式庫練習不需要 pandas；這一步用來展示如何管理額外套件。需要移除時用 uv remove pandas，不要手動刪掉 .venv 裡某個檔案。用 Git 差異查看 pyproject.toml 與 uv.lock 的變更。

步驟 4：執行程式

新增 analyze.py：

import pandas as pd
scores = pd.Series([70, 80, 90], name="score")
print(f"平均分數：{scores.mean():.1f}")

uv run python analyze.py

預期輸出 平均分數：80.0。這是虛構資料；實際學生資料先匿名化並遵守校方規範。若出現 ModuleNotFoundError，核對目前目錄、專案依賴與執行方式，而非直接安裝到全域 Python。uv 專案操作。

第四部分：專案管理與雙 CLI 協作（Project Context）

1. 為什麼資料夾很重要？

Agent 從你啟動的目錄取得工作脈絡與權限邊界。把來源、程式與產物分開，才能知道它用了哪些資料、寫到哪裡。建議目錄：

teaching-analysis/
├── AGENTS.md
├── CLAUDE.md
├── sources/
├── outputs/
├── analyze.py
├── pyproject.toml
└── uv.lock

把 .venv/、.env 與不適合公開的資料列入 .gitignore；忽略規則只是 Git 的追蹤設定，不是禁止 Agent 讀取的存取控制。每次任務前後檢查 git status、git diff 與未追蹤檔案，選擇性提交。

2. 使用 AGENTS.md／CLAUDE.md 建立 AI 協作指南

工具 本課指引檔 載入確認
Codex CLI 專案根目錄 AGENTS.md 在該目錄開始新會話，請它列出實際載入的指引與適用規則；再用一個可核對的小任務驗證
Claude Code 專案根目錄 CLAUDE.md 用 /context 檢查 Memory files，並測試輸出；共用規則時在 CLAUDE.md 寫入 @AGENTS.md

Codex 還有使用者層與子目錄的規則，AGENTS.override.md 可覆蓋同層預設檔案。Claude Code v2.1.277+ 可直接讀 AGENTS.md，但預設只有在工作目錄及其上層沒有 CLAUDE.md、.claude/CLAUDE.md 或 CLAUDE.local.md 時才採用；內建支援被停用、舊版或部分升級後首次會話也可能不可用。/config 的 Project instructions 可設定同時載入兩者。本課採 CLAUDE.md 匯入 AGENTS.md，兼顧既有版本與 Windows，不依賴 symlink。

這些文字提供 context，不是系統權限，更不保證模型每次都遵守。/permissions、實際 sandbox、檔案權限與人工驗收分別負責授權、隔離與品質。不要在規則內放 API 金鑰或學生個資。

來源：Codex AGENTS.md、Claude 專案記憶、Claude 權限。

可在 AGENTS.md 寫入以下可測的規則：

# 教材分析專案
- 使用繁體中文；先列出實際讀取的來源檔。
- sources/ 是原始資料，不修改；產物寫入 outputs/。
- Python 命令使用 uv run，不更動全域環境。
- 統計時列出筆數、缺值處理及公式；以虛構測例核對結果。
- 回報修改檔案、執行命令與結果，不把推測當成測試。

相鄰 CLAUDE.md 的內容：

@AGENTS.md

3. 如何讓 CLI 讀取專案設定？

從專案根目錄啟動新會話，先請工具列出規則與檔案，再給任務：

閱讀 AGENTS.md 與 analyze.py，說明目前輸入、平均公式及預期輸出。
只做閱讀，不修改檔案。指出需要哪些依賴，並列出驗證命令。

閱讀完成後再授權修改或執行。Claude 用 /context 檢查已載入的記憶檔；Codex 可請它說明適用的指引，並檢查 /status。AI 能自我介紹不表示規則已載入，仍需看檔案、工具紀錄與實際輸出。

總結

完成環境不是把所有工具裝齊，而是能在正確專案啟動一款 CLI，使用正確帳號與權限，讓 Python 在正確 .venv 執行，並驗證結果。交付版本紀錄、目錄結構、規則檔、80.0 的執行結果與 Git 差異，即可進入 單元四 與 單元五。
